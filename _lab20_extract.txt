Marco Teórico
De trazas simuladas a trazas distribuidas reales
En el Laboratorio 7, "order-service", "payment-service" e "inventory-service" eran tres archivos dentro del MISMO proceso de Node.js — una simplificación deliberada para enseñar el concepto de spans padre-hijo sin la complejidad de levantar varios servidores. En este laboratorio, esos tres "servicios" son TRES PROCESOS DE SISTEMA OPERATIVO DISTINTOS, comunicándose por HTTP real. La trazabilidad distribuida de verdad consiste en que el ID de traza viaje de un proceso a otro dentro de los encabezados HTTP (el estándar W3C Trace Context, encabezado "traceparent"), sin que el equipo tenga que programar esa propagación a mano — la auto-instrumentación de OpenTelemetry lo hace por ustedes.

Se reemplaza facade/app.js completo. A partir de este punto, el inventario SIEMPRE se resuelve por el microservicio (esa parte de la migración ya quedó permanente desde el Laboratorio 19); lo nuevo es la bandera para el pago.
facade/app.js (versión final)
const express = require('express');
const axios = require('axios');
const app = express();
app.use(express.json());
const STRANGLE_PAYMENT = process.env.STRANGLE_PAYMENT === 'true';
const INVENTORY_SERVICE_URL = process.env.INVENTORY_SERVICE_URL || 'http://localhost:4001';
const PAYMENT_SERVICE_URL = process.env.PAYMENT_SERVICE_URL || 'http://localhost:4002';
const MONOLITH_URL = process.env.MONOLITH_URL || 'http://localhost:4000';
app.post('/checkout', async (req, res) => {
const { orderId, productId, amount } = req.body;
try {
const invResp = await axios.get(`${INVENTORY_SERVICE_URL}/check-stock`, { params: { productId } });
if (!invResp.data.inStock) {
return res.status(409).json({ success: false, reason: 'sin stock', source: 'microservicio-inventario' });
}
if (STRANGLE_PAYMENT) {
const payResp = await axios.post(`${PAYMENT_SERVICE_URL}/process-payment`, { orderId, amount });
return res.status(payResp.status).json(payResp.data);
} else {
const payResp = await axios.post(`${MONOLITH_URL}/checkout-payment-only`, { orderId, amount });
return res.status(payResp.status).json(payResp.data);
}
} catch (err) {
if (err.response) return res.status(err.response.status).json(err.response.data);
console.error(err);
return res.status(500).json({ success: false, reason: 'error interno de la fachada' });
}
});
const PORT = process.env.PORT || 3000;
app.listen(PORT, () => console.log(`Fachada escuchando en ${PORT}, STRANGLE_PAYMENT=${STRANGLE_PAYMENT}`));

Parte C · Trazabilidad distribuida real entre los 3 servicios
Instalen las dependencias de OpenTelemetry con auto-instrumentación HTTP en LOS 3 servicios (monolito, inventario, pago) y en la fachada:
npm install @opentelemetry/sdk-node @opentelemetry/sdk-trace-node @opentelemetry/resources @opentelemetry/semantic-conventions @opentelemetry/auto-instrumentations-node @opentelemetry/api
(Ejecuten ese comando dentro de monolith/, inventory-service/, payment-service/ y facade/ — cada carpeta tiene su propio node_modules.)
tracing.js (idéntico en los 4 servicios, copien el mismo archivo en cada carpeta)
const { NodeSDK } = require('@opentelemetry/sdk-node');
const { ConsoleSpanExporter } = require('@opentelemetry/sdk-trace-node');
const { resourceFromAttributes } = require('@opentelemetry/resources');
const { ATTR_SERVICE_NAME } = require('@opentelemetry/semantic-conventions');
const { getNodeAutoInstrumentations } = require('@opentelemetry/auto-instrumentations-node');
const serviceName = process.env.OTEL_SERVICE_NAME || 'unknown-service';
const sdk = new NodeSDK({
resource: resourceFromAttributes({ [ATTR_SERVICE_NAME]: serviceName }),
traceExporter: new ConsoleSpanExporter(),
instrumentations: [getNodeAutoInstrumentations()],
});
sdk.start();
module.exports = sdk;
Agreguen require('./tracing'); como la PRIMERA línea de cada app.js (monolith, inventory-service, payment-service, facade).
